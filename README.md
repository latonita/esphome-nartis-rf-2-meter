**Нартис RF433-2 (Д101-2)**

# esphome-nartis-rf-2-meter

Чтение счётчиков **Нартис И100/И300/И500** (примерно с 2024 г.) по радиоканалу 443 МГц.
ESP32 с приёмопередатчиком эмулирует выносной дисплей НАРТИС-Д101-2.

Нужны **ESP32**, радиомодуль (**CMT2300A** или **CC1101**) и **серийный номер
счётчика** (12 цифр с шильдика).

> **Компонент экспериментальный** 🙈 Проверен на живых счётчиках, но на отдельных
> моделях и годах выпуска могут быть несостыковки. Обратная связь приветствуется.

# Радиомодуль — блок `radio:`

Радиочасть выбирается в YAML. Сам протокол от чипа не зависит: 2-FSK, 1200 бод,
±25 кГц, синхрослово `98 F3` — меняется только кремний под ним.

| `type` | Чип | Состояние |
| --- | --- | --- |
| `cmt2300a` | CMOSTEK CMT2300A | **по умолчанию**, проверен на десятке живых счётчиков |
| `cc1101` | TI CC1101 | новый, **проверен на паре счетчиков** |

## `type: cmt2300a`

Модуль управляется программным 3-проводным SPI, аппаратный `spi:` не нужен.

| Параметр | Обяз. | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `pin_sdio` | да | — | данные SPI (двунаправленный) |
| `pin_sclk` | да | — | тактовый сигнал SPI |
| `pin_csb` | да | — | выбор чипа (регистры) |
| `pin_fcsb` | да | — | выбор чипа (FIFO) |
| `pin_gpio3` | да | — | прерывание INT2 — **обязателен** |
| `rx_offset` | нет | `4699Hz` | **предпочтительный** способ: подстройка частоты приёма, **со знаком**, в герцах: `-3kHz`, `2500`, `0Hz`. Диапазон ±200 кГц. Тот же ключ и те же единицы, что у `cc1101` |
| `rx_center_offset` | нет | `758` | **устаревший** способ записи того же самого — в кодах CMT2300A (1 код ≈ 6.199 Гц), −4000…4000 |

`rx_offset` и `rx_center_offset` — **одна и та же настройка** (насколько приёмник
смещён от центра канала) в разных единицах, поэтому задавать их **одновременно
нельзя**: будет ошибка конфигурации. Если не задан ни один, остаётся проверенное
на железе значение по умолчанию.

Пересчёт точный в обе стороны: проверенные `758` кодов — это ровно
`rx_offset: 4699Hz` (758 × 6.199 Гц = 4698,8 Гц → 4699 Гц, а 4699 Гц → 758 кодов).
То есть рабочую конфигурацию можно переписать на герцы без изменения поведения.

```yaml
  radio:
    type: cmt2300a
    pin_sdio: GPIO19
    pin_sclk: GPIO18
    pin_csb: GPIO5
    pin_fcsb: GPIO21
    pin_gpio3: GPIO22
```

## `type: cc1101`

Обычный 4-проводный SPI, тоже программный — аппаратный `spi:` не нужен.

| Параметр | Обяз. | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `pin_sclk` | да | — | тактовый сигнал SPI |
| `pin_miso` | да | — | данные от чипа (он же GDO1) |
| `pin_mosi` | да | — | данные в чип |
| `pin_cs` | да | — | выбор чипа (CSn) |
| `pin_gdo0` | **нет** | — | прерывание по пакету; без него драйвер опрашивает статус по SPI |
| `rx_offset` | нет | `0Hz` | подстройка частоты приёма, **со знаком**, в герцах: `-3kHz`, `2500`, `0Hz`. Диапазон ±200 кГц |
| `output_power` | нет | `10` | мощность передатчика в дБм, −30…+10 (см. ниже) |
| `bandwidth` | нет | `81250Hz` | полоса приёмного фильтра, 58 кГц…812 кГц |
| `deviation` | нет | `25kHz` | девиация FSK, 1 кГц…200 кГц. **25 кГц — значение протокола**, менять без нужды не стоит |
| `foc_carrier_sense_gate` | нет | `false` | подвязать петли подстройки частоты и битовой синхронизации к детектору несущей (см. ниже) |

```yaml
  radio:
    type: cc1101
    pin_sclk: GPIO18
    pin_miso: GPIO19
    pin_mosi: GPIO23
    pin_cs: GPIO5
    pin_gdo0: GPIO22        # необязателен
```

Частотные параметры принимают запись с единицами (`25kHz`, `81250Hz`) и голое
число — оно всегда читается как герцы.

### `foc_carrier_sense_gate` — ручка для первого запуска на железе

Это настройка **пусконаладки**, а не повседневная. Она решает, работают ли петли
подстройки частоты (FOC) и битовой синхронизации постоянно или ждут детектора
несущей:

* `false` (по умолчанию) — `FOCCFG = 0x16`, затвор выключен. Петли подстраиваются
  непрерывно. Риск: пока мы долго ждём ответа счётчика, они подстраиваются под
  **шум** и успевают уползти к своим пределам.
* `true` — `FOCCFG = 0x36`, затвор включён. Петли заморожены, пока не сработает
  детектор несущей. Риск: слабая преамбула может его не поднять — и ответ будет
  потерян целиком.

Какое значение лучше на этом сигнале, **честно говоря, неизвестно**: 2-FSK, 1200
бод, девиация ±25 кГц — индекс модуляции h ≈ 41, то есть совсем не тот режим, под
который эти петли задумывались, и из даташита ответ не следует. Проверять надо
измерением: посчитать долю ответов **с сошедшейся CRC** при обоих значениях за
несколько десятков циклов. Само по себе появление байтов в FIFO ничего не
доказывает — сорвавшаяся петля тоже наполняет FIFO, только мусором.

> ⚠ **Мощность.** CC1101 в диапазоне 433 МГц выдаёт максимум около **+10 дБм**,
> тогда как настоящий дисплей НАРТИС-Д101-2 передаёт **+20 дБм**. То есть наш
> запрос уходит примерно на **10 дБ слабее**: приём от счётчика не страдает, а вот
> «докричаться» до него получится не всегда. Если связи нет или она на пределе —
> помогает модуль CC1101 с внешним усилителем (PA), а не увеличение
> `output_power`: выше +10 дБм чип всё равно не умеет.

> ⚠ **Зрелость.** Ветка CMT2300A отлажена на живых счётчиках. Ветка CC1101
> написана по тому же описанию PHY, но **на железе пока не проверена**. Если
> выбираете чип впервые — берите CMT2300A.

# Быстрый старт

```yaml
external_components:
  - source: github://latonita/esphome-nartis-rf-2-meter
    components: [nartis_rf_2_meter]

nartis_rf_2_meter:
  id: nartis
  address: "123456789012"    # 12 цифр с шильдика
  radio:
    type: cmt2300a
    pin_sdio: GPIO19
    pin_sclk: GPIO18
    pin_csb: GPIO5
    pin_fcsb: GPIO21
    pin_gpio3: GPIO22

  rssi:
    name: "Meter RSSI"

sensor:
  - platform: nartis_rf_2_meter
    name: "Active energy import total"
    tag: 0x00
    unit_of_measurement: kWh
    accuracy_decimals: 3
    device_class: energy
    state_class: total_increasing

text_sensor:
  - platform: nartis_rf_2_meter
    name: "Date/time"
    tag: 0x29

binary_sensor:
  - platform: nartis_rf_2_meter
    name: "Last read OK"
```

Полный пример со всеми сущностями — [`example_esp32.yaml`](example_esp32.yaml),
трёхфазный — [`example-3ph.yaml`](example-3ph.yaml).

# Параметры хаба

| Параметр | Обяз. | По умолчанию | Описание |
| --- | --- | --- | --- |
| `id` | да | — | идентификатор компонента |
| `address` | да | — | серийный номер, ровно 12 цифр |
| `radio` | да | — | радиомодуль и его выводы (см. выше) |
| `update_interval` | нет | `300s` | период опроса |
| `sources` | нет | `[list_2]` | что опрашивать (см. ниже) |
| `rssi` | нет | — | диагностический сенсор уровня сигнала, нужно только `name` |
| `frequency` | нет | из `address` | частота канала вручную. Обычно не нужна |
| `request_gap` | нет | `300ms` | пауза между запросами |
| `rf_rx_timeout` | нет | `1800ms` | ожидание ответа на одну попытку |
| `rf_retries` | нет | `2` | повторов при потере связи (0–10). Всего попыток = `1 + rf_retries` |

Частота вычисляется по серийному номеру и печатается в лог при старте.

Компонент объявлен как `MULTI_CONF`: несколько счётчиков описываются списком, и
у каждого свой блок `radio:` со своими выводами.

## Старый формат: выводы на верхнем уровне

До появления `radio:` пять выводов CMT2300A и `rx_center_offset` задавались прямо
в блоке компонента. Такие конфигурации **продолжают работать**: компонент сам
сворачивает их в неявный `radio: {type: cmt2300a, ...}` и печатает в лог
предупреждение с новым написанием.

```yaml
# устарело, но работает
nartis_rf_2_meter:
  address: "123456789012"
  pin_sdio: GPIO19
  pin_sclk: GPIO18
  pin_csb: GPIO5
  pin_fcsb: GPIO21
  pin_gpio3: GPIO22
  rx_center_offset: 758
```

Ограничения совместимости:

- старые ключи и `radio:` **взаимоисключающи** — одновременно их указать нельзя;
- все пять `pin_*` обязаны быть заданы вместе, иначе будет понятная ошибка;
- в новых конфигурациях используйте только `radio:` — плоские ключи будут удалены.

## sources — что опрашивать

Счётчик отдаёт заранее настроенные страницы; произвольный параметр запросить нельзя.
Каждый источник — отдельные запросы в цикле, поэтому лишние лучше не включать.

| Источник | Что даёт |
| --- | --- |
| `list_1` | список индикации 1 (обычно короткий: энергия + часы) |
| `list_2` | список индикации 2 (обычно полный) — **по умолчанию** |
| `fix_1` | реактивная энергия (TAG `0x0A`–`0x13`) |
| `fix_2` | мгновенные P/Q по фазам, U, I, частота |

Наборы списков настраиваются конфигуратором «Nartis Tools» и у разных счётчиков
разные. Если нужного параметра нет ни в одном списке — включите `fix_1` / `fix_2`.
Значения из списков и из фиксированных блоков сводятся в одну сущность.

```yaml
  sources: [list_2, fix_2]
```

# Сенсоры

У каждого сенсора задаётся **ровно один** ключ:

- `tag` — параметр из таблицы ниже;
- `status` — служебное: `active_tariff` (текущий тариф) или `tariff_count`
  (число тарифов); у `text_sensor` дополнительно `raw` (весь блок в hex).

Плюс стандартные параметры ESPHome (`name`, `unit_of_measurement`, `device_class`,
`state_class`, `icon`, `entity_category`, …).

`sensor` принимает любой `tag`, кроме `0x29`. `text_sensor` принимает любой,
включая `0x29` — часы публикуются строкой `2026-07-17 15:54:58`.

`binary_sensor` — одна диагностическая сущность: `true`, если последний цикл
получил все ответы от счетчика.

## bytes — незнакомый TAG

TAG вне таблицы (`0x2B`, `0x40`–`0x4F`) компонент декодировать не умеет и
отказывается гадать. Ширину значения можно задать вручную — при встрече
нераспознанного TAG компонент печатает в лог дамп страницы, по нему её и видно:

```yaml
  - platform: nartis_rf_2_meter
    name: "Неизвестный параметр"
    tag: 0x4A
    bytes: 4        # 1..9; значение публикуется без пересчёта
```

# Таблица параметров (TAG)

Возможны неточности; подробности и провенанс — в [`tags.md`](tags.md).

| TAG | Параметр | Единица |
| --- | --- | --- |
| `0x00` | Активная энергия, импорт, всего | кВт·ч |
| `0x01`–`0x04` | Активная энергия, импорт, тарифы 1–4 | кВт·ч |
| `0x05` | Активная энергия, экспорт, всего | кВт·ч |
| `0x06`–`0x09` | Активная энергия, экспорт, тарифы 1–4 | кВт·ч |
| `0x0A` | Реактивная энергия, импорт, всего | квар·ч |
| `0x0B`–`0x0E` | Реактивная энергия, импорт, тарифы 1–4 | квар·ч |
| `0x0F` | Реактивная энергия, экспорт, всего | квар·ч |
| `0x10`–`0x13` | Реактивная энергия, экспорт, тарифы 1–4 | квар·ч |
| `0x14` | Напряжение (однофазный счётчик) | В |
| `0x15` / `0x16` / `0x17` | Напряжение фаз L1 / L2 / L3 | В |
| `0x18`–`0x1A` | Линейное напряжение AB / BC / CA | В |
| `0x1B` | Ток (однофазный счётчик) | А |
| `0x1C` / `0x1D` / `0x1E` | Ток фаз L1 / L2 / L3 ⚠ | А |
| `0x1F` | Ток, объект `0x0E07` — не фаза C ⚠ | А |
| `0x20` | Активная мощность, сумма | Вт |
| `0x21`–`0x23` | Активная мощность фаз L1 / L2 / L3 | Вт |
| `0x24` | Реактивная мощность, сумма | вар |
| `0x25`–`0x27` | Реактивная мощность фаз L1 / L2 / L3 | вар |
| `0x28` | Частота сети | Гц |
| `0x29` | Дата и время | только `text_sensor` |
| `0x2A` | Температура | °C |
| `0x2C`–`0x3F` | То же, что `0x00`–`0x13`, на конец прошлого расчётного периода | кВт·ч / квар·ч |

⚠ Привязка токов к фазам определена по внутренним номерам объектов счётчика и
расходится с подписями в документации производителя. Если токи выглядят
перепутанными — проверьте по нагрузке.

# Диагностика

- **Счётчик не отвечает.** Проверьте `address` и частоту в логе при старте.
  Затем подстройте приёмник на ответ: он приходит на несколько кГц выше нашей
  передачи. У обоих чипов это `radio: rx_offset:` (в герцах, со знаком); у
  CMT2300A то же самое можно задать устаревшим `radio: rx_center_offset:` в кодах
  чипа (1 код ≈ 6.199 Гц, проверенные 758 кодов = `4699Hz`). На CC1101 проверьте
  также, что `output_power` не занижен: запас по передаче там и так небольшой.
- **CC1101: счётчик слышно, но ответы не декодируются.** Байты приходят, CRC не
  сходится — попробуйте `radio: foc_carrier_sense_gate: true` (см. раздел про
  `type: cc1101`) и сравните долю ответов с верной CRC с обоими значениями.
- **Часть сущностей без данных.** Счётчик прислал не всё — включите ещё источник
  в `sources`. Компонент пишет в лог, какой TAG никто не принёс.
- **`Previous cycle still running`.** `update_interval` меньше длительности цикла.
  Увеличьте интервал или уменьшите `rf_retries`.
- **Подробный лог.** На `DEBUG` видно ход опроса и разбор значений, на `VERBOSE` —
  сами кадры в hex:

  ```
  [D][nartis_rf_2_meter]: TX DI 0xF202 attempt 1 (28 bytes)
  [D][nartis_rf_2_meter]: RX rssi=-81 dBm (78 bytes)
  [D][nartis_rf_2_meter]:   TAG 0x00 = 35.4B.C9.00 (13191989 -> 13191.989 kWh)
  [D][nartis_rf_2_meter]:   -> 'Активная энергия, всего' = 13191.989 kWh (list)
  ```

  Для длинных строк добавьте `logger: tx_buffer_size: 1024`.
