**Нартис RF433-2 (Д101-2)**

# esphome-nartis-rf-2-meter

Чтение счётчиков **Нартис И100/И300/И500** (примерно с 2024 г.) по радиоканалу 443 МГц.
ESP32 с модулем CMT2300A эмулирует выносной дисплей НАРТИС-Д101-2.

Нужны **ESP32**, модуль **CMT2300A** и **серийный номер счётчика** (12 цифр с шильдика).

> **Компонент экспериментальный** 🙈 Проверен на живых счётчиках, но на отдельных
> моделях и годах выпуска могут быть несостыковки. Обратная связь приветствуется.

# Подключение CMT2300A

Модуль управляется программным 3-проводным SPI, аппаратный `spi:` не нужен.

| Параметр | Назначение |
| --- | --- |
| `pin_sdio` | данные SPI (двунаправленный) |
| `pin_sclk` | тактовый сигнал SPI |
| `pin_csb` | выбор чипа (регистры) |
| `pin_fcsb` | выбор чипа (FIFO) |
| `pin_gpio3` | прерывание INT2 — **обязателен** |

# Быстрый старт

```yaml
external_components:
  - source: github://latonita/esphome-nartis-rf-2-meter
    components: [nartis_rf_2_meter]

nartis_rf_2_meter:
  id: nartis
  address: "123456789012"    # 12 цифр с шильдика
  pin_sdio: GPIO19
  pin_sclk: GPIO18
  pin_csb: GPIO5
  pin_fcsb: GPIO21
  pin_gpio3: GPIO22
  
  rssi:
    name: "Meter RSSI"

sensor:
  - platform: nartis_rf_2_meter
    name: "Active energy import total"
    tag: 0x00
    unit_of_measurement: kWh
    accuracy_decimals: 3
    device_class: energy
    state_class: total_increasing

text_sensor:
  - platform: nartis_rf_2_meter
    name: "Date/time"
    tag: 0x29

binary_sensor:
  - platform: nartis_rf_2_meter
    name: "Last read OK"
```

Полный пример со всеми сущностями — [`example_esp32.yaml`](example_esp32.yaml),
трёхфазный — [`example-3ph.yaml`](example-3ph.yaml).

# Параметры хаба

| Параметр | Обяз. | По умолчанию | Описание |
| --- | --- | --- | --- |
| `id` | да | — | идентификатор компонента |
| `address` | да | — | серийный номер, ровно 12 цифр |
| `pin_*` | да | — | подключение CMT2300A (см. выше) |
| `update_interval` | нет | `300s` | период опроса |
| `sources` | нет | `[list_2]` | что опрашивать (см. ниже) |
| `rssi` | нет | — | диагностический сенсор уровня сигнала, нужно только `name` |
| `frequency` | нет | из `address` | частота канала вручную. Обычно не нужна |
| `request_gap` | нет | `300ms` | пауза между запросами |
| `rf_rx_timeout` | нет | `1800ms` | ожидание ответа на одну попытку |
| `rf_retries` | нет | `2` | повторов при потере связи (0–10). Всего попыток = `1 + rf_retries` |
| `rx_center_offset` | нет | `758` | подстройка частоты приёма в кодах CMT2300A (1 код ≈ 6.2 Гц) |

Частота вычисляется по серийному номеру и печатается в лог при старте.

## sources — что опрашивать

Счётчик отдаёт заранее настроенные страницы; произвольный параметр запросить нельзя.
Каждый источник — отдельные запросы в цикле, поэтому лишние лучше не включать.

| Источник | Что даёт |
| --- | --- |
| `list_1` | список индикации 1 (обычно короткий: энергия + часы) |
| `list_2` | список индикации 2 (обычно полный) — **по умолчанию** |
| `fix_1` | реактивная энергия (TAG `0x0A`–`0x13`) |
| `fix_2` | мгновенные P/Q по фазам, U, I, частота |

Наборы списков настраиваются конфигуратором «Nartis Tools» и у разных счётчиков
разные. Если нужного параметра нет ни в одном списке — включите `fix_1` / `fix_2`.
Значения из списков и из фиксированных блоков сводятся в одну сущность.

```yaml
  sources: [list_2, fix_2]
```

# Сенсоры

У каждого сенсора задаётся **ровно один** ключ:

- `tag` — параметр из таблицы ниже;
- `status` — служебное: `active_tariff` (текущий тариф) или `tariff_count`
  (число тарифов); у `text_sensor` дополнительно `raw` (весь блок в hex).

Плюс стандартные параметры ESPHome (`name`, `unit_of_measurement`, `device_class`,
`state_class`, `icon`, `entity_category`, …).

`sensor` принимает любой `tag`, кроме `0x29`. `text_sensor` принимает любой,
включая `0x29` — часы публикуются строкой `2026-07-17 15:54:58`.

`binary_sensor` — одна диагностическая сущность: `true`, если последний цикл
получил все ответы от счетчика.

## bytes — незнакомый TAG

TAG вне таблицы (`0x2B`, `0x40`–`0x4F`) компонент декодировать не умеет и
отказывается гадать. Ширину значения можно задать вручную — при встрече
нераспознанного TAG компонент печатает в лог дамп страницы, по нему её и видно:

```yaml
  - platform: nartis_rf_2_meter
    name: "Неизвестный параметр"
    tag: 0x4A
    bytes: 4        # 1..9; значение публикуется без пересчёта
```

# Таблица параметров (TAG)

Возможны неточности; подробности и провенанс — в [`tags.md`](tags.md).

| TAG | Параметр | Единица |
| --- | --- | --- |
| `0x00` | Активная энергия, импорт, всего | кВт·ч |
| `0x01`–`0x04` | Активная энергия, импорт, тарифы 1–4 | кВт·ч |
| `0x05` | Активная энергия, экспорт, всего | кВт·ч |
| `0x06`–`0x09` | Активная энергия, экспорт, тарифы 1–4 | кВт·ч |
| `0x0A` | Реактивная энергия, импорт, всего | квар·ч |
| `0x0B`–`0x0E` | Реактивная энергия, импорт, тарифы 1–4 | квар·ч |
| `0x0F` | Реактивная энергия, экспорт, всего | квар·ч |
| `0x10`–`0x13` | Реактивная энергия, экспорт, тарифы 1–4 | квар·ч |
| `0x14` | Напряжение (однофазный счётчик) | В |
| `0x15` / `0x16` / `0x17` | Напряжение фаз L1 / L2 / L3 | В |
| `0x18`–`0x1A` | Линейное напряжение AB / BC / CA | В |
| `0x1B` | Ток (однофазный счётчик) | А |
| `0x1C` / `0x1D` / `0x1E` | Ток фаз L1 / L2 / L3 ⚠ | А |
| `0x1F` | Ток, объект `0x0E07` — не фаза C ⚠ | А |
| `0x20` | Активная мощность, сумма | Вт |
| `0x21`–`0x23` | Активная мощность фаз L1 / L2 / L3 | Вт |
| `0x24` | Реактивная мощность, сумма | вар |
| `0x25`–`0x27` | Реактивная мощность фаз L1 / L2 / L3 | вар |
| `0x28` | Частота сети | Гц |
| `0x29` | Дата и время | только `text_sensor` |
| `0x2A` | Температура | °C |
| `0x2C`–`0x3F` | То же, что `0x00`–`0x13`, на конец прошлого расчётного периода | кВт·ч / квар·ч |

⚠ Привязка токов к фазам определена по внутренним номерам объектов счётчика и
расходится с подписями в документации производителя. Если токи выглядят
перепутанными — проверьте по нагрузке.

# Диагностика

- **Счётчик не отвечает.** Проверьте `address` и частоту в логе при старте.
  Затем подстройте `rx_center_offset`: ответ приходит на несколько кГц выше нашей
  передачи, и приёмник надо навести на него.
- **Часть сущностей без данных.** Счётчик прислал не всё — включите ещё источник
  в `sources`. Компонент пишет в лог, какой TAG никто не принёс.
- **`Previous cycle still running`.** `update_interval` меньше длительности цикла.
  Увеличьте интервал или уменьшите `rf_retries`.
- **Подробный лог.** На `DEBUG` видно ход опроса и разбор значений, на `VERBOSE` —
  сами кадры в hex:

  ```
  [D][nartis_rf_2_meter]: TX DI 0xF202 attempt 1 (28 bytes)
  [D][nartis_rf_2_meter]: RX rssi=-81 dBm (78 bytes)
  [D][nartis_rf_2_meter]:   TAG 0x00 = 35.4B.C9.00 (13191989 -> 13191.989 kWh)
  [D][nartis_rf_2_meter]:   -> 'Активная энергия, всего' = 13191.989 kWh (list)
  ```

  Для длинных строк добавьте `logger: tx_buffer_size: 1024`.
